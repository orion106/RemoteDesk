# Remote Desk — администрирование компьютерных классов

Windows-приложение на .NET 10 (WPF) для администрирования компьютерных классов и инвентаризации учебного корпуса. Поддерживает Windows и Astra Linux на управляемых ПК, поиск Active Directory, удалённую помощь, GLPI и общую базу оборудования на TrueNAS.

**Исходники и инструкции опубликованы полностью.** Готовые архивы Windows и TrueNAS пока не опубликованы в [Releases](https://github.com/orion106/RemoteDesk/releases): их загрузка не завершилась. Ниже приведены команды для самостоятельной сборки. Архив Windows, когда он появится в релизе, нужно распаковать целиком и запустить `RemoteAssist.exe`.

## Возможности версии 1.1

- Планы пяти этажей корпуса «Д», кабинеты и коридоры, расстановка техники перетаскиванием.
- Открытие карточки двойным щелчком на карте, ручное добавление оборудования, связи компьютер–монитор, номера телефонов и рабочих мест.
- Фотографии, инвентарные и серийные номера, история изменений и архив оборудования.
- Картриджи: совместимые модели, установка и замена, группы «Запас», «Установлены», «На заправке», «Списанные».
- Импорт XLSX с предварительным просмотром, сверки наличия и экспорт ведомостей без установленного Excel.
- Сервер ASP.NET Core + SQLite: личные учётные записи, проверка версий при совместной работе, просмотр локальной копии без связи, резервные копии.
- Аудитории, каталог программ, мониторинг, задания, питание, удалённая помощь и отдельное обновление программы «Нагрузка».

## Быстрый старт из исходников

Нужны Windows x64, Git и **.NET SDK 10**. Для серверного контейнера — Docker с Linux-контейнерами. Команды ниже выполняются в корне клонированного репозитория.

```powershell
git clone https://github.com/orion106/RemoteDesk.git
cd RemoteDesk
dotnet restore .\RemoteAssist\RemoteAssist.csproj
dotnet build .\RemoteAssist\RemoteAssist.csproj -c Release
dotnet run --project .\RemoteAssist\RemoteAssist.csproj -c Release
```

Переносимая Windows-сборка с включённой средой .NET:

```powershell
dotnet publish .\RemoteAssist\RemoteAssist.csproj -c Release -r win-x64 --self-contained true -o .\publish
.\publish\RemoteAssist.exe
```

Копируйте **всю папку `publish`**, а не только EXE. Реальная база, учётные записи и личные документы не входят в исходники или сборку. Раздел общей инвентаризации требует отдельно запущенного сервера; запуск Windows-приложения не разворачивает сервер автоматически.

### Общий сервер инвентаризации

```powershell
docker build -f deploy/inventory.Dockerfile -t remoteassist-inventory:1.1 .
docker save -o remoteassist-inventory-1.1.tar remoteassist-inventory:1.1
```

Дальше следуйте [установке на TrueNAS](INVENTORY-SERVER.md): подготовьте SSD/HDD datasets, пароль владельца и доверенный TLS-сертификат, загрузите образ и настройте [Custom App YAML](deploy/truenas-inventory.yaml). Адреса и пути в YAML являются примерами. Не публикуйте пароль, сертификат с закрытым ключом или содержимое datasets в Git.

В Windows-приложении откройте **Инвентаризация → Подключение**, укажите `https://имя-сервера:8443`, войдите и загрузите кабинеты с планов. Затем **Карта → этаж → кабинет / коридор → + Добавить технику**. Сохраните карточку и разместите объект из списка «Не расставлено».

Клиент и сервер обновляйте вместе. Скрипт `deploy/Update-LocalInventory.ps1` предназначен только для ранее созданного локального тестового стенда на диске `D:`; это не установщик для нового ПК и не сценарий установки TrueNAS.

На целевых ПК не устанавливается постоянный агент Remote Desk. Для операций временно передаются PowerShell/Python-сценарии через SMB/SFTP. Нужны заранее предоставленные права Windows и SSH/sudo; приложение не меняет политики, брандмауэр или настройки загрузчика. Мониторинг и расписания работают, пока приложение открыто, в том числе свёрнуто.

## Запуск

Скопируйте **всю папку publish**, включая DLL рядом с EXE, на Windows 10/11 x64 Pro или Enterprise. Запустите `RemoteAssist.exe`. Сборка содержит .NET, отдельно устанавливать среду выполнения не требуется.

Параметры AD и прежних функций находятся в меню **Настройки**, разделённом на группы **Подключение**, **Рабочие столы**, **Обновление нагрузки** и **Оформление**. Переключение групп сохраняет черновик. Общие кнопки **Сохранить** и **Отмена** применяют или отменяют изменения сразу во всех группах. Параметры GLPI, SSH, Viewer, защиты профилей и мониторинга находятся в раскрывающемся блоке **Настройки классов** внизу новых разделов.

При первом запуске откройте **Настройки → Подключение**:

1. Выберите текущую учётную запись Windows либо указанную учётную запись AD.
2. Для отдельного аккаунта введите логин `DOMAIN\user` или `user@domain` и пароль.
3. При необходимости задайте контроллер домена и DN области поиска, например `OU=Office,DC=contoso,DC=local`. Эта область применяется к поиску пользователей и компьютеров: OU только с компьютерами не содержит пользовательские объекты.
4. Нажмите **Проверить подключение**. Проверка использует черновик настроек и ничего не сохраняет.
5. В группе **Рабочие столы** проверьте маски основного поиска, в **Обновление нагрузки** задайте отдельные маски обновления. В **Оформление** выберите тему. Нажмите **Сохранить**.

Логин и пароль из настроек применяются к **Active Directory, Windows-адаптеру классов и обновлению нагрузки**: доступу к файлам, WMI, показу уведомлений и закрытию согласованных процессов. При выборе текущей записи Windows используется она. Поиск сеансов (`query session`, WTS) и `mstsc /shadow` выполняются под текущей учётной записью Windows. Для этих действий ей нужны соответствующие права на удалённых ПК. Чтение AD само по себе не требует полного администрирования домена.

## Пароль и настройки

Флажок **Запомнить пароль в Windows** сохраняет пароль в Windows Credential Manager для текущего пользователя на этом компьютере. Приложение создаёт собственную запись `RemoteAssist/AD/…` для сочетания контроллера и логина. Пароля нет в JSON и аргументах процессов.

При отключённом флажке пароль действует только до закрытия приложения. **Удалить сохранённый пароль** помечает его для удаления; операция выполняется после **Сохранить**. **Отмена** отменяет редактирование, включая запланированное удаление. После удаления потребуется заново ввести пароль для поиска под отдельным аккаунтом.

Настройки сохраняются в `%LOCALAPPDATA%\RemoteAssist\settings.json`. Существующие настройки загружаются с новыми полями по умолчанию. Выбранная ранее тема сохраняется; у новой установки тема тёмная.

## Маски компьютеров

По умолчанию разрешены:

```text
dc*-*
note-dc*-*
```

Маски редактируются по одной на строку. `*` соответствует любому числу символов; остальные символы трактуются буквально. Имена сравниваются без учёта регистра по короткому имени ПК, а не DNS-суффиксу. Подойдут `DC01-WS01` и `NOTE-DC2-15`; `WS-15` не будет опрашиваться. Требуется хотя бы одна маска; `*` разрешает все имена.

Маски действуют и при поиске компьютера, и при поиске сеансов пользователя. Текст в строке поиска дополнительно сужает результат и не интерпретируется как LDAP-фильтр. Для просмотра всех ПК в разрешённой области выберите **Компьютеры** и нажмите **Найти** с пустым запросом. Для поиска пользователей введите ФИО, логин или UPN.

## Интерфейс и сеансы

- **Главная** — поиск, таблица сеансов, обновление и отмена. Для активного подтверждённого сеанса доступна кнопка **Подключиться**.
- **Настройки** — единое меню с группами «Подключение» (учётная запись и AD), «Рабочие столы» (маски поиска сеансов), «Обновление нагрузки» (маски обновления) и «Оформление» (тема).
- **Аналитика** — компьютеры и сеансы текущего опроса. Ошибки считаются по компьютерам до фильтрации по пользователю; незавершённые и отменённые опросы помечаются.
- **Обновление нагрузки** — поиск установок по сохранённым маскам, выбор нового `Service.exe`, замена и запрос согласия для занятых файлов. Кнопка «Настройки обновления» открывает соответствующую группу общего меню.
- Меню сворачивается до иконок. На небольшом окне доступны прокрутка рабочей области и горизонтальная прокрутка таблицы; ширину столбцов можно менять. Полный обрезанный текст виден в подсказке.
- Основное окно и общие стили размещены в `RemoteAssist/MainWindow.xaml`, новые разделы — в `RemoteAssist/LabView.xaml`. Используются стандартные элементы WPF.

Опрос ограничен восемью параллельными задачами. Команда `query session` имеет тайм-аут 15 секунд, а результат хранится в памяти одну минуту. **Обновить** игнорирует кэш. Сохранение настроек отменяет текущий опрос и очищает таблицу. Завершившийся старый запрос не добавляет строки в новые результаты.

WTS — синхронный системный RPC: его завершение зависит от сетевых тайм-аутов Windows. При отмене такого запроса интерфейс остаётся доступным, результаты отменённого поиска не применяются.

Перед открытием mstsc приложение повторно проверяет ID, домен и логин владельца сеанса. Оно сообщает **Запущено подключение**, но не утверждает, что mstsc успешно открыл рабочий стол.

## Подготовка удалённых ПК

На целевых ПК должны быть доступны службы и правила брандмауэра для удалённого опроса сеансов и RDP. Учётная запись Windows, запускающая приложение, должна иметь права просмотра и удалённого управления сеансами.

В групповой политике: **Конфигурация компьютера → Административные шаблоны → Компоненты Windows → Службы удалённых рабочих столов → Узел сеансов удалённых рабочих столов → Подключения → Задать правила для удалённого управления пользовательскими сеансами** — выберите **Полное управление с разрешения пользователя**. Приложение само не меняет политики или брандмауэр.

## Обновление нагрузки

1. Откройте **Настройки → Обновление нагрузки**, введите маски, например `dc*-*`, и нажмите **Сохранить**. Они независимы от масок рабочих столов; при первой настройке пусты. Пустое поле разрешено для сохранения других настроек, но поиск нагрузки требует хотя бы одну маску. На вкладке обновления показываются сохранённые маски; поиск сам настройки не меняет. Используются общий контроллер домена и область поиска AD; отключённые учётные записи компьютеров исключаются.
2. Нажмите **Найти программу**. Проверяются `C:\Program Files\MMIS Lab\Plany` и `C:\Program Files (x86)\MMIS Lab\Plany` со всеми подкаталогами, включая `ServiceUpdate`. Дополнительно поддерживается буквально указанный нестандартный путь `C:\Program Files(86)\MMIS Lab\Plany\ServiceUpdate`. Ссылки и junction пропускаются с диагностикой.
3. Нажмите **Выбрать Service.exe**. Файл можно выбрать на своём ПК или в доступной сетевой папке. Проверяются имя, PE-заголовки и целостность секций исполняемого файла. Создаётся отдельная заблокированная от записи копия, отображаются версия и SHA-256. Программа не скачивает обновления и не запускает выбранный файл. Именно выбранный файл является источником обновления: номер версии информационный, сравнение выполняется по SHA-256.
4. Проверьте отметки в таблице и нажмите **Обновить найденные**. Обрабатываются отмеченные установки, максимум четыре компьютера одновременно; установки на одном ПК последовательно. Совпадающие файлы получают статус **Уже обновлён**. Закрытия приложений на этом шаге нет.
5. Для строк **Занят** нажмите **Принудительный запрос обновления**. В каждом активном сеансе, использующем этот конкретный файл, появится системное окно **Да/Нет**. По умолчанию выбран ответ **Нет**. Если пользователей несколько, до закрытия любого процесса требуется согласие всех.

Текст уведомления:

> Доступно обновление программы “Нагрузка”. Сохраните работу. При нажатии “Да” приложение будет закрыто. Если оно не закроется за 15 секунд, оно будет завершено принудительно; несохранённые данные могут быть потеряны. Обновить сейчас?

Ответ **Нет**, отсутствие ответа в течение пяти минут, отключённый сеанс или невозможность подтвердить владельца откладывают обновление. Для повторного запроса сначала повторите обычное обновление: если файл всё ещё занят, кнопка снова станет доступна. Никакого закрытия по тайм-ауту нет.

После согласия выполняется попытка обычного закрытия локальной командой `taskkill` на целевом ПК без `/F` и `/S`. Через 15 секунд оставшиеся согласованные процессы завершаются через WMI. Перед закрытием повторно проверяются PID, полный путь, время запуска, владелец и сеанс. Новая копия программы требует нового запроса. Другие программы с именем `Service.exe` не завершаются. После замены нагрузка автоматически не запускается.

Новый файл сначала копируется во временный файл рядом с целевым и проверяется по SHA-256. Оригинал заменяется через `File.Replace`, с уникальной резервной копией `Service.exe.backup-<дата>-<идентификатор>` в том же каталоге. При неудачной проверке выполняется восстановление оригинала. При обрыве связи в момент замены показывается **Результат не подтверждён**: повторное обычное обновление проверит актуальный SHA-256. Если проверка невозможна или `Service.exe` отсутствует, администратору нужно проверить сохранённую резервную копию. Она автоматически не удаляется.

Конфигурация `Service.exe.config`, другие файлы приложения и база данных не изменяются. Обновление структуры базы через UserManager — отдельная операция, которую Remote Desk не выполняет; следуйте документации поставщика программы «Нагрузка».

Для обновления нужны доступ к административной папке `\\ПК\C$`, права изменения каталогов приложения, доступ WMI/DCOM к `root\cimv2`, запросу и управлению процессами, а также WTS Message/Query для уведомлений в сеансах. Обычно эти права предоставляет доменная учётная запись администратора целевых ПК. WinRM и установленный агент не требуются. Программа не меняет правила брандмауэра, политики и сторонние сетевые подключения. Отсутствие доступа показывается отдельно от отсутствия программы и занятости файла.

Журнал текущей работы виден на вкладке; журнал попыток замены, контрольных сумм и резервных копий сохраняется в `%LOCALAPPDATA%\RemoteAssist\UpdateLogs\YYYY-MM-DD.jsonl` без паролей. Запись `Prepared` без подтверждённого завершения требует повторной проверки файла. Выбранный пакет хранится в `%LOCALAPPDATA%\RemoteAssist\UpdatePackages` до смены файла или закрытия Remote Desk. После аварийного завершения там могут остаться неиспользуемые копии. При потере связи уникальные временные файлы могут остаться рядом с целевым файлом; их пути записаны в журнале.

**Отмена** прекращает новые действия и игнорирует поздние ответы на запросы. Начатая замена сначала проверяется или откатывается. Системные SMB/WMI/WTS-вызовы могут ожидать сетевого тайм-аута; окно остаётся доступным, новая операция начнётся после завершения текущих вызовов. При закрытии Remote Desk во время обновления программа отменяет операцию и дожидается её безопасного завершения.

### Приёмка в доменной среде

На тестовых ПК под выбранной доменной учётной записью проверить обе папки Program Files, вложенный ServiceUpdate, совпадающий и отличающийся файл. На запущенной тестовой «Нагрузке» проверить обычный проход со статусом **Занят**, затем ответы **Нет**, **Да**, отсутствие ответа, закрытие зависшей копии и два пользовательских сеанса. Проверить, что посторонний `Service.exe` остаётся запущенным. Дополнительно проверить недоступный C$, отказ WMI/WTS, сохранность оригинала при прерванном копировании и проверку результата после восстановления связи. Для этих проверок использовать тестовые установки и сохранённые данные.

## Сборка и проверки

Требуются Windows и .NET SDK 10.

```powershell
dotnet build .\RemoteAssist\RemoteAssist.csproj -c Release
dotnet run --project .\RemoteAssist.Tests\RemoteAssist.Tests.csproj -c Release
dotnet publish .\RemoteAssist\RemoteAssist.csproj -c Release -r win-x64 --self-contained true -o .\publish
```

Проверки покрывают маски и экранирование LDAP, два формата логина, отмену/сохранение настроек, удаление и восстановление пароля, миграцию старых настроек, исключение ПК из опроса, подсчёт ошибок и опрос 100 компьютеров. Проверка Windows Credential Manager использует уникальную синтетическую запись и удаляет её после выполнения.

Дополнительные проверки обновления покрывают независимость масок, миграцию настроек, PE-файл и неизменность выбранного пакета, поиск в подкаталогах, пропуск junction, блокировку файла, отказ доступа, копирование, резервные копии, откат, неопределённый результат при обрыве связи, согласие нескольких пользователей, тайм-ауты, смену PID/сеанса и отмену. Проверки WMI/WTS-сценариев используют подставные реализации и не закрывают настоящие приложения пользователей.

Тестовый процесс проверяет XAML, привязки и создание окон. Рендеры четырёх разделов, светлой/тёмной темы и масштабов 100–200% сохраняются в `artifacts/ui`. Это тестовые данные, которые не попадают в приложение или переносимую сборку. Рендеры не заменяют приёмку на реальных мониторах с разным DPI.

Реальная проверка LDAP-авторизации, сетевых прав, подключения к сеансу и удалённого обновления с пользовательским подтверждением требует доменной среды. На текущем компьютере вне домена эта проверка не выполнялась.
